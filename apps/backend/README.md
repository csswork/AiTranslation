# VPS 后端：账号、托管翻译、订阅与管理

本应用在 VPS 上提供三部分：共用 API 和两套独立界面。

| 部分 | 建议域名 | 使用者 | 内容 | 状态 |
| --- | --- | --- | --- | --- |
| 用户管理界面（用户端） | `app.huaci.app` | 注册用户 | 注册登录、账户总览、订阅、账单、用量与会话，只操作本人数据（U1–U8） | 已上线 |
| API | `api.huaci.app` | 扩展、官网、两套界面 | 认证、用户、额度、托管翻译、支付与管理接口 | 扩展接口（访客试用、登录、状态、托管文字翻译）、官网登录状态接口与 Creem 支付回调已实现，暂由用户端主机提供 |
| 管理员界面（管理端） | `admin.huaci.app` | 运营管理员 | 用户、套餐、订单、点数账本、托管服务配置、异常与审计（A1–A9） | 首版已上线（本地 `http://admin.localhost:8787`） |

两套界面共用后台数据，但入口、登录和接口权限分别验证。功能范围见 [两套界面的审核稿](../../docs/backend/ui-scope.md)。

技术栈：Node.js 22、[Hono](https://hono.dev/)（服务端渲染 HTML，界面不需要浏览器脚本）、PostgreSQL（`pg`），Google 登录使用 [Arctic](https://arcticjs.dev/)。会话、验证码和账号模型由本应用自行实现，以满足资料最小化要求。

## 扩展接口、访客试用与托管翻译

扩展接口挂在 `/api/extension`，只接受 `chrome-extension://<EXTENSION_IDS>` 来源的跨域请求，凭 `Authorization: Bearer` 扩展会话令牌认证，不使用 Cookie。

- **访客试用**（`POST /api/extension/guest`）：扩展安装后静默调用，不需要用户操作。
  - 服务端建立没有邮箱的访客账户和扩展会话，按规则赠送访客点数（默认 50，不过期）。
  - 同一网络 30 天内最多 3 次：IP 只存带密钥的哈希，IPv6 按 /64。
  - 全站每天最多发放 2000 份，超出的访客账户照建但为 0 点。
  - 返回欢迎页地址 `/welcome?link=<一次性关联码>`。
- **欢迎页识别重装**：欢迎页读写本站的浏览器标记 Cookie（随机值，库里只存哈希，扩展卸载后仍在）。
  - 第一次打开：写入标记。
  - 标记属于另一个访客：同一浏览器重装，扩展会话接回旧访客，新访客删除，不多发点数。
  - 标记属于正式账户：新访客的点数作废，提示登录；不会凭 Cookie 自动登录。
- **注册与合并**：注册赠送点数默认 200，不过期。合并时访客剩余点数作为一笔 `transfer` 转入，用量记录随之转移，访客账户删除，领取记录保留转化结果。
  - 扩展登录换令牌时带上 `guest_token`，访客合并进刚登录的账户。
  - 在同一浏览器的网页上登录时，浏览器标记属于访客的也会合并，并把扩展会话改到正式账户，扩展随之登录。
- **登录**：扩展在当前窗口的新标签页打开 `/extension/authorize`（带 `redirect_uri`、S256 `code_challenge`、`state`）。
  - 用户在用户端登录并在确认页同意后，回到扩展的回调页 `chrome-extension://<扩展 ID>/src/auth/callback.html`，只带一次性授权码（2 分钟、只能用一次）。
  - 确认页的 CSP `form-action` 只放行这次请求的扩展来源。
  - 扩展用 `POST /api/extension/token` 提交授权码与 `code_verifier`，换取扩展会话令牌。令牌在库里只存哈希。
- **状态**：
  - `GET /api/extension/me` 返回用户类型（访客或注册）、用户名、点数余额、订阅（`unlimited`、方案、状态、本期结束）、托管是否可用，以及注册可得点数。
  - `POST /api/extension/logout` 撤销当前扩展会话。
- **网页登出同步**：授权码与正式账户的扩展会话记录授权网页会话 ID；网页登出或撤销该网页会话时，关联扩展一并失效，其他浏览器不受影响。网页注册时从访客转入的扩展会话也建立同样关联。扩展在用户端页面加载、恢复或重新可见时核对 `/me`，收到 401 后清除令牌和本地状态；通知只接受当前环境的完整用户端来源，不读取网页 Cookie。迁移 `007` 会使无法判断浏览器归属的旧版正式扩展会话失效，需要重新授权一次；访客会话保留。
- **托管文字翻译**（`POST /api/extension/translate`）：
  - **订阅用户**不扣点，界面显示「无限使用」，用量照常记录。管理员可设隐藏的每月字数上限，超过返回 429 `fair_use`。
  - **其他用户**固定按 500 个 Unicode 字符 = 1 点精确预扣，没有单次最低扣点。例如 1 字符扣 0.002 点、250 字符扣 0.5 点；模型失败逐笔全额返还。空白与标点也计入字符数，emoji 等补充平面字符不按 UTF-16 码元重复计费。
  - 错误码：402 余额不足，403 托管服务被冻结，413 超长，429 过频，502 模型失败（已返还），503 未配置或已停用。
- **模型**：主力是 DeepSeek 官方 `deepseek-flash`；配置了 `HOSTED_FALLBACK_API_KEY` 时，主力失败或 20 秒超时会改用备用，默认 Fireworks 美国节点上的 DeepSeek V4.1 Flash。
- **统计元数据**：每次请求在 `usage_events` 记录用户类型、服务商与模型、输入和输出 token、估算成本（按管理员设置的单价）、耗时、错误码、目标与源语言，以及国家代码（配置了地理请求头时），不保存原文或译文。
- **被拒绝的请求**：点数不足、托管服务被冻结、超长、过频、超过订阅用户月度上限、服务停用时不调用模型、不扣点，记入 `usage_rejections`（用户、原因、字数、需要的点数、目标语言、国家，不存原文）；每个用户每种原因每分钟最多记 10 条。格式错误的请求不记录。与 `usage_events` 分开，成本、请求数和月度用量的统计口径不受影响。
- **账本**：`credit_ledger` 只追加。扣点、返还和作废都关联到具体的点数发放（`grant_id`），余额只统计有效发放的剩余部分。账本 `amount_units`、请求及拒绝记录 `cost_units`、访客发放 `granted_units` 均用 PostgreSQL `bigint` 保存整数字符额度，代码使用 `BigInt`；500 单位 = 1 点，不用浮点数计算或逐次舍入。
- **展示与接口**：余额、发放、转入、扣点和流水均显示两位小数；公开 API 返回十进制展示字符串，不暴露换算参数。`credits.available` 单独表示是否还有精确额度，不能用显示的 `0.00` 判断额度已耗尽。赠送和补发配置支持两位小数，换算后按整数入账。完整约定、接口例子和升级步骤见 [精确额度记账](../../docs/backend/credit-accounting.md)。

## 订阅与收款（Creem）

Creem 作为 Merchant of Record 处理付款、税费与收据，适配器在 `src/billing/creem.js`。

- **结账**：`POST /billing/checkout`（月付或年付）调用 Creem 创建结账会话，元数据只放内部用户 ID，然后跳转到 Creem 结账页。
- **回调**：`POST /webhooks/creem` 用原始请求体验签（`creem-signature`，HMAC-SHA256）。
  - 事件按平台事件 ID 去重；同一订阅只接受不早于已处理事件的状态。处理失败返回 500，由 Creem 重试。
  - 回调里的姓名、邮箱、国家不入库，只保存订阅、客户与交易 ID、状态、税前金额与币种。
- **权益**：以下状态在本期结束前有效：`active`、`trialing`、`paid`、`scheduled_cancel`（已取消续订）、`past_due`（扣款重试中）。
- **收入记录**：订阅收入按 `subscription.paid` 记录，首期不与 `checkout.completed` 重复计算；退款按交易的税前比例折算回写。
- **客户门户**：`POST /billing/portal` 打开 Creem 客户门户（取消续订、换卡、发票）。

## 管理员界面（A1–A9）

管理端使用独立主机名（`ADMIN_ORIGIN`，开发默认 `http://admin.localhost:8787`），与用户端在同一进程，按主机名分流。会话 Cookie、同源校验和权限都与用户端分开，用户端会话在管理端无效。界面只有中文。

- **配色**：与用户端、官网共用 `theme` Cookie 和切换按钮，生产环境写在父域，`SHARED_COOKIE_DOMAIN` 需同时覆盖管理端主机名。
- **A1 登录**：
  - 管理员只能用命令行指定：`npm run admin -- grant <email>`，另有 `revoke`、`reset-2fa`、`list`。
  - 登录用管理端专用的邮箱验证码，再做 TOTP 二步验证，首次登录时绑定。密钥加密存储，同一验证码不能重放。
  - 本地开发默认跳过二步验证（设 `ADMIN_REQUIRE_2FA=1` 可测试完整流程）；没有发信服务时，验证页直接弹出验证码。生产环境两者都不会发生。
  - 完成邮箱验证码与二步验证后，管理端会话与浏览器 Cookie 保留 30 天，关闭浏览器再打开仍可登录；从登录成功时起计时，访问不顺延。待二步验证的会话仍为 12 小时，不能访问管理页面。本地跳过二步验证时，从邮箱验证成功起计时。
  - 退出登录、撤销管理员资格或重置二步验证后，已有登录立即失效。此期限独立于用户端的 `SESSION_DAYS`；更新前已登录的管理员需重新登录一次才能获得 30 天有效期。
- **A2 运营概览**（近 7、30、90 个自然日，含今天；与上一个等长日历周期对比，按 `REPORT_TIMEZONE` 切分）：沿用用户总览的卡片、留白与明暗配色，分为 API 消耗、经营收支、用户与使用、语言与地区、性能与异常。核心指标保留零值，主要图表提供空状态；模型、收入、支出、累计趋势与用户排行可折叠展开。汇总与图表共用报表时区的自然日边界，不混用滚动小时窗口。
  - 经营：净收入、总支出、利润与利润率；每日收支柱状图与利润折线组合，支持负值；支出构成环形图。累计收入、支出与利润走势另可展开查看。
  - 收入：毛收入、退款、续费收入、付费用户人均（ARPPU）、MRR 与年化；每日新购与续费，按方案、按账单国家，其他币种单列。
  - 支出：模型 API（默认按用量估算，`api_cost_source = bills` 时改按录入的账单，两者不会重复计入）、支付手续费（按设置的比例 + 每笔固定费用估算）、录入的固定支出（按天分摊）；每日支出与构成。
  - API 消耗（页面最前面）：输入（含缓存命中）与输出 token、估算成本、每万字成本、每次请求平均 token、被拒绝的请求；每日 token 堆叠图、模型路由环形图、成功与失败请求堆叠图、每日模型成本面积图。模型、被拒原因与用户类型成本可展开查看。卡片与每日序列都计入缺少服务商标记的历史记录，缓存 token 只计一次。
  - 指标卡片：安装、新注册、活跃用户、托管请求、字数、估算成本、USD 收入与毛利、有效订阅与 MRR，带环比和迷你趋势线。
  - 趋势：增长（安装、注册、活跃、订阅）、每日请求（成功与失败）、累计收入与成本。
  - 转化漏斗：安装 → 用过翻译 → 注册 → 订阅，以分步进度条展示各步人数和转化率，手机自动排列成两列。
  - 构成：请求来自哪类用户、模型路由（主力、备用、失败）、订阅方案、按用户类型的成本。
  - 语言与地区：本地 Equal Earth 世界地图，可切换安装、使用和收入着色；悬停显示该地区的安装、安装后注册、请求、使用人数和 USD 税前净收入。语言偏好作为全局汇总放在地图旁，不推断地区与语言的关联。底图覆盖 236 个国家与地区，小地区有记录时用定位点显示；地区统计不再限制前 15 条，底图未覆盖的代码保留文字记录。地图来源与构建方式见 [地图数据说明](ui/admin/data/README.md)。
  - 地区使用两位国家代码；安装与使用的国家来自反向代理地理请求头（`GEO_COUNTRY_HEADER`），收入来自 Creem 账单国家。不采集具体位置，不向第三方发送统计，不使用外部地图 API。
  - 时段与性能：星期 × 小时热力图，耗时分位数与分布，请求字数分布。
  - 其他：访客领取结果，异常与降级，用量最高的用户。
  - 图表在服务端生成，复用用户总览的本站提示脚本：日期趋势显示当天各系列数值与报表时区，环形图显示数量／金额及占比，热力图与直方图可查看零值区间。提示支持悬停、触摸点击及键盘导航，并限制在视口内；未加载脚本时保留原生 SVG 提示。没有新增图表依赖或放宽 CSP。
- **API 用量**（`/api-usage`）：每位使用托管翻译的用户在 7、30、90 天或全部时间里的成功、失败、被拒次数，字数、输入与输出 token、扣点、估算成本和最近使用时间，可排序、搜索；用户详情页另有该用户的 API 消耗汇总（近 30 天与全部）、用过的模型、逐条请求（含 token、成本、耗时、语言）与被拒记录。
- **收支**（`/expenses`）：录入服务器、域名、发信、推广、模型 API 账单等支出，可设一次性、每月或每年循环（循环的按天分摊，可设结束日）；金额按美元记录。录入与删除都写审计，删除只做标记。
- **A3 用户**：搜索、详情、补发点数、冻结或恢复托管服务、撤销会话；每项操作必须填写原因。
- **A4、A7 规则与服务配置**：访客与注册点数（支持两位小数）、同一网络次数与周期、每日领取总量、托管开关、单次上限、订阅用户隐藏上限、价格展示、模型成本单价、收支口径（支付手续费费率、模型成本按估算还是按账单）。换算固定为 500 字符 = 1 点，不再提供每点字数配置。修改立即生效并写审计；模型和 Creem 只显示是否已配置。
- **A5 订阅与订单**：按状态筛选。退款在 Creem 后台发起，结果经回调写回。
- **A6 点数账本**：收入单独保留表格，可按类型筛选；支出和翻译请求按 UTC 日展示图表，支持本月、近 7 天、近 30 天筛选、悬停数值及展开明细。用户详情使用同一套收支展示；图表聚合全量数据，不受明细条数上限影响。
- **A8 异常**：失败的托管请求、按错误码统计、支付回调处理状态。
- **A9 操作审计**：管理员、时间、操作、对象、原因与变更前后的值。

### Google One Tap

- 登录页在浏览器已登录 Google 时自动弹出“以某账号继续”（Chrome 走 FedCM），选中后组件把 Google 签名的 ID token 交给页面，隐藏表单提交到 `POST /auth/google/one-tap`。
- 服务端用 Google 公钥（JWKS，按 Cache-Control 缓存）验证 RS256 签名，并检查 `iss`、`aud`（本应用客户端 ID）、有效期，以及登录页为本次显示生成、存在短期 Cookie 里的一次性 nonce；同一凭证不能重放。只读取 `sub`、`email`、`email_verified`。账号判断与授权码流程共用（`googleSignIn`），从官网进入时同样返回官网。
- CSP 只在登录页放开 Google 组件需要的 `https://accounts.google.com/gsi/`（script、frame、connect、style，样式另含 `'unsafe-inline'` 供不支持 FedCM 的浏览器定位弹窗）；其他页面保持严格策略。
- 需要 Google OAuth 客户端的“已获授权的 JavaScript 来源”包含用户端地址（本地 `http://localhost:8787`，生产 `https://app.huaci.app`）。

### 多语言、配色与页头页脚

用量与点数页（`/usage`）将赠送、转入、补发和失败返还列为点数收入，保留原有表格样式；预扣和作废单独作为点数支出图，翻译请求按成功、失败和处理中展示堆叠柱状图。两图支持本月、近 7 天、近 30 天和日期悬停；各类明细可以展开。收入表格不受图表时间范围影响；图表统计所选范围内的全部记录，明细最多 100 条，管理端全局账本最多 300 条。支出按账本流出统计，失败返还计入收入，区别于总览里只计成功请求的净消耗口径。

账户总览提供本月、近 7 天、近 30 天的托管用量筛选，可按文字与图片识别查看。指标为精确点数消耗、请求次数和模型返回的输入／输出词元用量，配有按 UTC 天汇总的柱状图、请求趋势与用量堆叠图；仅展示本人记录，不展示模型成本或金额。点数以成功请求的整数额度汇总后格式化，失败已返还、处理中与被拒绝请求不计入消耗；请求次数包含已完成的成功与失败调用，图片识别与后续文字翻译各算一次。未返回词元数据的调用不估算词元，自带 API Key 的请求不经过服务端、不纳入统计。订阅用户显示无限使用，将点数卡片与消耗图替换为翻译字符数。空数据保留筛选与零值指标，图表显示空状态；图表由服务端生成 SVG，与管理端共用绘制器，无新增运行依赖或 CSP 放宽。用户总览通过本站脚本增强日期提示：悬停立即显示当天数据（含零值），用量图展示输入、输出与合计；日期按当前语言显示并标注 UTC，点数由服务端精确格式化为两位小数。支持触摸点击、键盘左右键与 Home/End 切换日期，Esc 关闭；未加载脚本时保留原生 SVG 提示。

- 界面支持与官网相同的 11 种语言（`i18n/locales.json`），阿拉伯语为从右到左排版。语言按与官网共用的 `lang` Cookie、浏览器 `Accept-Language` 的顺序确定，页头下拉切换后记住。时间以 UTC 显示。
- 中文文案本身就是翻译键，写在 `t('…')` 或 `k('…')` 里；译文在 `i18n/<code>.json`。`npm run i18n` 提取文案，优先沿用官网已有的同一句译文，其余用 DeepSeek 补齐（Key 读 `apps/backend/.env.local` 或根目录 `.env.local` 的 `DEEPSEEK_API_KEY`）；`npm run check:i18n` 与测试检查缺失、多余、占位符和译文错乱。
- 配色与官网一致：默认跟随系统，页头按钮切换后写入 `theme` Cookie，服务端直接输出 `<html data-theme>`，不会闪烁。`account.js` 负责即时切换、语言下拉自动提交和登录等待反馈；没有脚本时表单照常提交。
- 用户端与管理端的验证码、Google 登录、二步验证和扩展授权确认提交时显示等待状态并防止重复提交；Google One Tap 通过同一提交保护显示进度。返回页面后恢复控件，原生表单与授权选择字段保持可用；不需要放宽 CSP。
- 语言与配色和官网同步：两边都读写同名的 `lang`、`theme` Cookie（不设 HttpOnly，只是显示偏好）。生产环境设置 `SHARED_COOKIE_DOMAIN=huaci.app`，偏好写在父域，任一站点切换后另一站点下次打开即跟随；官网选「自动」会清掉 `lang`，两边都回到按浏览器语言。会话 Cookie 不受影响，仍只属于用户端主机。本地开发时 Cookie 不区分端口，localhost 上的两个站点天然共用。
- 账户入口：未登录是实心「登录」按钮，已登录是首字母圆标 + 用户名（首字母取用户名第一个字符，不使用头像），窄屏只显示圆标；官网页头使用相同的样式。
- 页头、页脚与官网首页使用相同的结构、类名、样式和链接（链接指向官网当前语言的页面），只是最右侧多出账户入口。`test/web.test.mjs` 对照 `apps/web/public/index.html` 检查链接一致；改动任何一边的页头或页脚时同步另一边。

### 官网登录状态

- `GET /api/web/session`：官网带 credentials 读取，返回 `signedIn`、用户名、点数余额与账户地址（未登录时返回登录地址），不含邮箱或内部 ID。只读，`Cache-Control: no-store`。
- 只对 `WEB_ORIGINS` 白名单里的来源返回 `Access-Control-Allow-Origin` 与 `Allow-Credentials`。官网与用户端同属 `*.huaci.app`，属于同站跨源请求，用户端只绑定自身主机的 `SameSite=Lax` 会话 Cookie 会被附上，不需要把 Cookie 放宽到父域。
- `/login?return=<官网地址>`：登录完成后回到该地址；只接受 `WEB_ORIGINS` 里的来源，已登录时直接返回。

### 账号与数据

- `users` 只有 email、username、邮箱验证时间和创建/更新时间；用户名默认生成 `user_xxxxxxxx`，用户可改为 3–24 位小写字母、数字、`_` 或 `-`。
- Google 只申请 `openid email`，只读取 `sub`、`email`、`email_verified`；姓名、头像等不读取、不保存。Google 已验证的邮箱与已有账号一致时直接绑定到该账号；邮箱未验证时拒绝，请用户改用邮箱验证码。
- 验证码 6 位数字、10 分钟有效、最多尝试 5 次，数据库只存 HMAC；同一邮箱 60 秒内只能发一次、每小时最多 5 次，同一来源地址每小时最多 20 次（内存计数，不落库）。超过一天的验证码记录在发新码时删除。
- 用户端与扩展的会话令牌为 32 字节随机数，数据库只存 SHA-256；只记录类型（网站/扩展）和时间，不记录 IP、User-Agent、设备或位置。有效期由 `SESSION_DAYS` 控制，默认一年（365 天），有效使用时滚动续期，服务端每小时最多写一次最近使用时间与有效期；提高配置期限后，仍有效的旧会话也会在下一次使用时续期，无需重新登录。访问用户端页面或官网查询状态时，同时刷新用户端浏览器 Cookie。
- 扩展的有效请求会分别检查并续期自身会话与授权它的网页会话；即使客户长期不打开用户端，也不会因为关联网页会话先到期而中断扩展服务。扩展请求不读取或写入网页 Cookie。连续一年无有效访问、主动退出或被管理员撤销后仍需重新登录；已经过期或撤销的会话不会恢复。退出或过期的会话在下次登录时删除。管理端仍独立固定为 30 天。
- 试用点数通过只追加的 `credit_ledger` 发放，每个账号一条 `trial:<user_id>`，绑定新的登录方式不会重复发放。余额由服务端按账本汇总。试用点数与有效期（默认 100 点、30 天）是占位值。

### 安全

- 会话 Cookie：HttpOnly、SameSite=Lax；HTTPS 下为 Secure 并使用 `__Host-` 前缀，只属于用户端主机。
- 所有 POST 必须来自本站（Origin 等于 `APP_ORIGIN`，或浏览器标记 `Sec-Fetch-Site: same-origin`），否则 403。
- CSP：`default-src 'none'`，脚本只允许本站（`script-src 'self'`，无内联脚本）；页面带 `noindex`、`no-store`、`X-Frame-Options: DENY`，HTTPS 下加 HSTS。静态资源地址带内容哈希，可长期缓存。
- 生产环境配置校验：`APP_ORIGIN` 必须是 HTTPS，必须设置 `AUTH_SECRET` 与 `TRIAL_CREDITS`，且不能使用 console 发信，所以**接入正式发信服务前无法在生产环境启动**。

## 本地开发

需要 Node.js 22+ 和本机 PostgreSQL（例如 Postgres.app）。

```sh
cd apps/backend
npm ci
cp .env.example .env.local        # 按需填写；AUTH_SECRET 可用 openssl rand -hex 32 生成
createdb huaci_dev                 # Postgres.app 的命令位于 /Applications/Postgres.app/Contents/Versions/latest/bin
npm run migrate
npm run dev                        # http://localhost:8787，修改 src/、ui/ 后自动重启
```

仓库根目录也可以运行 `npm run migrate:backend`、`npm run dev:backend`、`npm run test:backend`。

登录时验证码打印在服务日志里，形如 `[开发发信] 登录验证码 → you@example.com：123456`。

管理端：先在用户端用某个邮箱登录一次，再运行 `npm run admin -- grant you@example.com`，然后打开 `http://admin.localhost:8787`。验证页会直接弹出验证码（也打印在服务日志里），本地不需要二步验证。

模拟扩展安装（访客领取）：`curl -X POST -H 'origin: chrome-extension://abcdefghijklmnopabcdefghijklmnop' http://localhost:8787/api/extension/guest`，返回的 `welcomeUrl` 就是欢迎页。

### Google 登录（可选）

在 Google Cloud Console 创建“Web 应用”类型的 OAuth 客户端，授权回调地址填 `http://localhost:8787/auth/google/callback`（生产环境为 `<APP_ORIGIN>/auth/google/callback`），把客户端 ID 和密钥写入 `.env.local` 的 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`。未配置时登录页和账户页不显示 Google 入口。

服务端要直接请求 Google 令牌端点。本机如需经代理访问 Google，在 `.env.local` 设置 `HTTPS_PROXY`（支持 `http://` 与 `socks5://`，如 `socks5://127.0.0.1:7898`）：Node 自带的 `fetch` 不读系统代理，否则浏览器能打开 Google、回调时却会提示“Google 登录没有完成”。

### 测试

```sh
createdb huaci_test
npm test
```

测试使用 `postgres://localhost:5432/huaci_test`（可用 `TEST_DATABASE_URL` 覆盖），每个测试文件开始时会**清空并重建**该库；为防误删，数据库名必须以 `_test` 结尾。Google 登录用替身测试，不访问 Google。

# VPS 后端：账号、托管翻译、订阅与管理

本目录是独立后端应用的入口。目前只有职责与实施说明，尚未引入运行框架、数据库依赖或可启动的服务。

本应用在 VPS 上提供三部分：共用 API 和两套独立界面。

| 部分 | 建议域名 | 使用者 | 内容 |
| --- | --- | --- | --- |
| API | `api.huaci.app` | 扩展、官网、两套界面 | 认证、用户、额度、托管翻译、支付与管理接口 |
| 用户管理界面（用户端） | `app.huaci.app` | 注册用户 | 注册登录、账户总览、订阅、账单、用量与会话，只操作本人数据（U1–U8） |
| 管理员界面（管理端） | `admin.huaci.app` | 运营管理员 | 用户、套餐、订单、点数账本、托管服务配置、异常与审计（A1–A9） |

两套界面共用后台数据，但入口、登录和接口权限分别验证。首版功能范围见 [两套界面的审核稿](../../docs/backend/ui-scope.md)，待审核后进入实现。

## 职责

| 模块 | 后端负责的内容 |
| --- | --- |
| 认证 | 简单注册、Google / X 等平台 OAuth、用户与会话管理；优先打通 Chrome 扩展登录，官网共用账号；管理员登录单独验证并启用二步验证 |
| 额度 | 注册试用点数、服务端余额、预扣、结算、失败退款、幂等账本 |
| 托管翻译 | 文字、图片和视频的受控接口；成本计量、限额、超额停用；模型 Key 由后端保存 |
| 订阅与支付 | 套餐、结账入口、用户订阅状态、支付服务 Webhook 验签及重放防护 |
| 用户管理界面 | 登录、注册、账户总览、订阅、账单、用量记录、邮箱与登录方式、会话管理 |
| 管理员界面 | 运营概览、用户、套餐与试用配置、订单与订阅、点数账本、托管服务配置、异常任务与操作审计 |
| 数据 | 必要的 email、用户名、内部用户 ID 和认证记录，以及订单、订阅、额度流水、管理操作审计与必要的运维记录 |

用户自带 Key 的模式继续由扩展直接调用所选服务商；收费针对托管翻译。试用额度和付费额度必须由后端判断，前端与扩展只展示状态。

账号资料只保留必要的 email 与 username，不建立头像、昵称或额外个人资料字段。OAuth 返回的其他个人资料不保存、缓存或写入日志；认证框架的默认用户模型需要按此要求定制。

支付服务通过适配器接入。现阶段讨论过 Creem 与 Stripe；实际启用的服务商仍需结合商户审核与收款条件确定。订阅是否生效由后端验证支付事件，不能以浏览器跳转到成功页面为依据。

## 实施时的目录

以下是后续新增代码时采用的划分，目前不创建空实现：

```text
src/
  auth/             用户、OAuth、会话
  credits/          额度与账本
  translation/      托管文字、图片、视频翻译
  billing/          套餐、订阅、支付服务适配器
  webhooks/         已验签、可重试、可幂等处理的支付事件
  admin/            管理接口、管理员权限与操作审计
  config/           服务端配置
ui/
  account/          用户管理界面（按所选框架组织）
  admin/            管理员界面（按所选框架组织）
migrations/         数据库迁移
test/               服务端测试
deploy/             VPS 容器、反向代理与运维配置
```

官网 HTML 与最基本的登录状态展示放在 `../web`；API、用户管理界面和管理员界面归本应用，随 VPS 服务部署；Chrome 内界面放在 `../extension`。数据库与密钥位于 VPS，管理权限在服务端执行。数据库建议使用 PostgreSQL；具体后端框架和认证实现将在下一步确定。

## 开始实现的顺序

1. 审核两套界面的首版范围；确定后端运行栈、数据库和 VPS 部署方式，建立基础服务与迁移入口。
2. 用户、OAuth 和扩展登录；扩展展示当前用户、试用点数与订阅状态，用户管理界面提供登录与账户总览，官网复用相同接口。
3. 额度账本和试用点数；接通托管文字、图片和视频入口与限额。
4. 支付结账、订阅、Webhook，以及用户管理界面的订阅与账单。
5. 管理员界面、成本观察、限流、备份与上线验证。

托管模式上线前，要补充相应的数据处理和隐私说明，并实测各类翻译成本，再确定点数换算与价格。

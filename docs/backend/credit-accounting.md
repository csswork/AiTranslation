# 精确额度记账

## 计量与展示

文字托管固定按 **500 个 Unicode 码点 = 1 点** 计量；一个码点占 1 个内部额度单位，空格、标点、换行也计入。补充平面字符（例如单个 emoji）计 1 个码点；组合字符和由多个码点组成的 emoji 按其实际码点数量计量。不做 Unicode 归一化，不按 token 或输出长度收费。

| 输入字符数 | 实际扣点 | 扣点展示 |
| --- | --- | --- |
| 1 | 0.002 | 0.00 |
| 250 | 0.5 | 0.50 |
| 500 | 1 | 1.00 |
| 501 | 1.002 | 1.00 |
| 1100 | 2.2 | 2.20 |

不设置单次最低扣点；拆成多次请求和合并请求的总扣点相同。点数是客户估算用量的展示单位，界面不公开每点字数；两位小数只用于展示，不用于累计、计费、授权或转账。四舍五入后各条流水之和可能不等于展示余额变化，精确账本才是余额依据。

用户端 `/usage`、管理员用户详情与全局 `/ledger` 将正数流水列为点数收入（赠送、转入、补发、失败返还），负数流水列为支出（预扣与作废）。支出图显示账本流出总额，失败返还在收入中单列，不把支出图当作净消耗或余额变化；账户总览的成功请求消耗口径保持不变。图表按 UTC 自然日聚合所选范围内的全部记录，请求数量按 `usage_events` 统计，包含成功、失败和处理中，不因一笔请求拆扣多笔赠送而重复计数。收入表格保留最近的正数流水，不受图表时间范围影响；支出与请求明细按图表范围显示最近记录（用户端和管理员用户详情最多 100 条，全局账本最多 300 条）。汇总及悬停数值均用整数额度格式化，只在绘制 SVG 坐标时转为浮点数。

## 数据约定

`src/credits/units.js` 集中处理转换与字符统计。数据库用 PostgreSQL `bigint`，服务端计算用 JavaScript `BigInt`，`pg` 读出的整数文本直接转为 `BigInt`，禁止先经 `Number` 或浮点乘法。

| 表 | 字段 | 含义 |
| --- | --- | --- |
| `credit_ledger` | `amount_units` | 有符号的精确额度：发放、转入、补发、扣减、返还和作废 |
| `usage_events` | `cost_units` | 本次预扣额度；失败时由账本返还，原预扣记录保留 |
| `usage_rejections` | `cost_units` | 余额不足等拒绝所需额度；未计算时为 NULL |
| `guest_claims` | `granted_units` | 本次实际发放的访客额度；未发放或重复领取作废为 0 |

余额来自未过期发放及其关联流水之和，不新增独立余额缓存。按用户事务锁串行预扣，足额才扣；每次预扣关联用量记录和具体发放。失败按原始整数额度返还，重复返还幂等，过期发放不会因返还重新生效。访客转入和重复领取作废沿用相同单位，不能先把余额格式化为点数。

订阅用户预扣为 0，界面显示无限使用；请求字符数与模型成本仍记录，隐藏用量上限继续由服务端判断。视频中的文字字幕沿用文字计量，音视频托管没有另设收费实现。

图片托管分两步：`/api/extension/read-image` 使用服务端 DeepSeek Flash 识别文字与坐标，再由 `/api/extension/translate` 按实际提交的识别文字精确计量（同样 500 个码点 = 1 点）。图片识别不额外扣点，空图、识别失败也不扣点。识别记录为 `kind=image`、`chars=0`、`cost_units=0`，记录 token 与模型成本，不重复计入翻译字数；文字翻译失败仍按原账本返还。

识图前必须验证扩展会话、托管开关、冻结状态及精确正余额（订阅用户无需余额），并检查订阅隐藏上限。每个用户每小时识图次数由管理端 `hosted_image_hourly_requests` 控制，默认 60 次，0 表示暂停；长图每个切片和失败识别都计次，并发请求不能绕过；扩展框选的多个区域会拼成一张图识别，按拼图（超长时按其切片）计次。识图提示词让模型按文字块返回（对话框、旁白、段落，说明竖排并忽略注音），固定用温度 0、不开思考。扩展送检前会把图片补白成正方形，坐标在扩展里换算回原图。请求体最多 8 MiB。图片和识别文字不落库或日志，只有计费元数据。坐标重画不发请求；缓存原文重新翻译时按新请求计量。

赠送环境默认值、管理员赠送设置和补发输入按展示点数接受最多两位小数，再通过十进制文本转换为整数额度。例如 `0.29` 点入账 145 单位。拒绝负数、科学计数法和超出两位的小数输入。500 的换算固定，不再支持 `CHARS_PER_CREDIT` 或 `chars_per_credit` 设置。

## 公开接口与前端

`/api/extension/me`、翻译响应、官网 `/api/web/session` 中的 `credits` 统一为：

```json
{"balance":"0.00","available":true}
```

这表示仍可能剩有不足展示精度的额度，不能据此判断余额耗尽。`available` 只表示余额大于零；本次请求是否足额仍由服务端精确预扣决定，余额为正也可能返回 402。API 不返回内部额度或每点字数。

翻译响应 `cost`、访客申请 `granted`、登录合并 `transferred`、`offers.signupCredits` 都是两位小数的十进制展示字符串。账户余额、欢迎页、弹窗、设置页、用户流水和管理端报表使用同一展示精度；仅本地化数字分隔符，不以显示值进行额度运算。扩展的旧数字缓存可继续展示，刷新后使用新版接口值。

## 旧数据与发布

追加迁移 `008_exact_credit_units.sql`，将旧 `amount`、`cost`、`granted` 等字段改为 `*_units` 并乘 500。旧 100 点扣过 3 点，升级后仍有 97 点（48,500 单位）；不把旧请求重新按字符计费，也不修改历史赠送和扣费。迁移后只对新请求采用精确计量。

1. 备份数据库，停止旧后端。
2. 运行 `npm run migrate:backend`，确认包含迁移 008；删除旧换算环境配置。
3. 启动新版后端，检查 `/healthz`，同步发布扩展与官网文案。
4. Chrome 开发版重新加载扩展，正式版通过商店更新；刷新账户页面后检查状态与用量。

迁移后不能仅回退旧代码；需要回滚时一起恢复迁移前备份。未执行迁移时服务端会拒绝启动。本地与生产分别使用各自数据库、API 地址和发布配置，测试仅允许使用专用 `huaci_test` 库。

## 验证

`apps/backend/test/credits.test.mjs` 覆盖小额连续扣减、拆分与合并等价、最后一单位、Unicode 字符、并发不透支、跨发放预扣与幂等返还；`credits-migration.test.mjs` 从旧结构验证等值迁移和可重跑。扩展的点数显示测试覆盖小数位、本地化、旧缓存，以及显示 `0.00` 时的可用状态。

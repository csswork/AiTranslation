# 整站翻译

> 状态：纳入扩展 **2.3.0**，商店提交状态见 [发布记录](releases/2.3.0.md)。在无头 Chrome for Testing 150 上用本地端到端脚本验证过（翻译接口用桩代替，见第四节）；原生右键菜单、真实平台与本机翻译的整条链路仍需人工确认。

## 一、用户能做什么

- 普通网页空白处右键，「双语阅读这篇文章」下面是勾选项「翻译这个网站」。勾上后这个网站（按域名，含子域名：在 `2ch.sc` 上开启，`nozomi.2ch.sc` 等也翻译；反过来在子域名上开启不覆盖上级域名）的页面都自动翻译成默认目标语言，新打开的页面、页面后来加载的内容（无限滚动、单页应用换页）也一样，直到再次点它取消勾选。
- 勾选状态跟着当前标签页的网站切换。内置 PDF 阅读器里与双语阅读一起隐藏；新标签页、`chrome://`、本地文件、扩展页面等翻译不了的页面不显示（拿不到网址的标签页也一样，那里本来注入不了脚本）。
- 刚勾上时页面上一定有反馈：右下角立即出现「正在翻译这个网站…」；页面已经是目标语言时说明「这个页面已经是 X，不用翻译；这个网站上其他语言的页面会自动翻译」；页面上找不到要翻的文字时也说一声。普通的页面加载只在真正翻译时显示小条，首屏翻完后收起，之后滚动时安静地继续翻。出错时小条留着：「重试」「打开设置」（错误带设置入口时；本机翻译直接打开下载语言包的位置）「关闭整站翻译」。
- 取消勾选、点小条上的「关闭整站翻译」或在设置页移除后，所有打开着的该网站页面立即恢复原文，不用刷新。在子域名页面上取消勾选（或点「关闭整站翻译」）会去掉名单上所有覆盖它的项，包括上级域名，否则这个页面仍会翻译；设置页的「移除」只去掉那一项。
- **用量确认**：第一次用会花钱的平台（点数翻译、自带 API Key 的 ChatGPT / DeepSeek / DeepL）开启时，页面上弹出确认框，说明会消耗较多点数或 API 用量，可以：
  - 「改用本机翻译」（默认按钮；浏览器不支持本机翻译时不出现）：整站翻译单独改用本机翻译，其他功能的平台不变；
  - 「继续使用 X」；
  - 「取消」/ Esc / 点遮罩：不开启，撤回勾选。
  选了前两项之一后不再询问（`settings.siteCostConfirmed`）。本机翻译不花钱，从不弹。
- **设置页「整站翻译」卡片**：
  - 「整站翻译使用的平台」：默认「跟随翻译平台（当前平台名）」，也可以单独选一个（`settings.siteProvider`，空字符串表示跟随）。
  - 开着整站翻译的网站列表，可以逐个移除或全部移除。

## 二、实现

| 文件 | 内容 |
| --- | --- |
| `src/lib/sites.js` | `AITrSites`：网站名单（`chrome.storage.local` 的 `siteTranslate`，域名数组，最多 500 个），`hostOf` 只认 http(s)；`covers` / `match` 按域名与子域名匹配，`set` 用于页面上的开关，`remove` 用于设置页 |
| `src/lib/settings.js` | `siteProvider`、`siteCostConfirmed` 两个设置；`AITrSettings.siteProvider(settings)` 给出实际使用的平台 |
| `src/background.js` | 勾选菜单 `ai-translate-site`（`type: 'checkbox'`，`page` 上下文，紧跟双语阅读）；`syncPageMenus` 按当前标签页的网站更新勾选，`tabs.onUpdated` 换网址与名单变化时也同步；`toggleSite` 处理勾选、确认框（向顶层框架发 `site-confirm`）、写名单；`site-top-host` 按 `sender.tab.url` 告诉跨源子框架顶层域名 |
| `src/content/site.js` | 常驻内容脚本（顶层框架，以及与顶层同一网站的子框架），监听名单与设置，翻译、恢复原文、状态小条、确认框 |
| `src/options/` | 「整站翻译」卡片 |
| `test/menu.mjs` | 菜单项、勾选同步、确认流程（取消 / 改用本机翻译 / 只问一次 / 本机翻译不问 / 非 http(s) 网页） |

### 翻译方式

- 与区域翻译一样按**文字节点原地替换**，不改页面结构，链接、按钮照常可用。代价是一句话被行内元素切开时（`Click <a>here</a> to continue`）分段翻译，语序可能不自然。RTL 目标语言不改页面的 `dir`，免得打乱布局。
- 恢复时只换回仍是我们写入的译文的节点；页面后来自己改过的文字保持页面的值。页面改了已翻译的节点时按新值重新翻译。
- **框架**：子框架与顶层被名单上的同一项覆盖（同一网站，含子域名）时各自翻译自己的文字，包括 `<frameset>` 老网站（如 2ch.sc 的 `2ch.html`，菜单和正文都在 `<frame>` 里，顶层没有文字，点版块后内容框架换成 `nozomi.2ch.sc` 这类子域名页面）和同站 `iframe`；在框架里点链接换页面也照常翻译。同源时直接读顶层网址，跨源（子域名）时向 service worker 发 `site-top-host`。别的网站嵌进来的框架（广告、视频播放器）即使该网站也在名单上也不翻；只开了子域名时，它嵌在上级域名页面里也不翻。确认框只在顶层弹；子框架不显示进度和说明，只在出错时显示自己的小条；顶层是 `<frameset>` 时不提示「没有找到要翻的文字」。开启前就已打开、还没有内容脚本的旧标签页，补注入只到顶层，子框架要刷新后才翻。
- 网页组件的**开放 shadow root** 里的文字也翻译，并监听其中的变化；封闭的进不去（扩展自己的界面都在封闭 shadow root 里）。shadow root 在我们扫描之后才挂上的（组件延迟定义）会漏掉。
- 不翻译：`script`/`style`/`code`/`pre`/`kbd`/`samp`/`var`/`svg`/`math`/输入框等里面的文字、`translate="no"` 与 `.notranslate`、可编辑区域、没有字母的文字、超过 1500 字的单个文字节点。- 请求走现有的 `translate-batch`（`AITrRequests` 长连接，可取消），`providerId` 用整站翻译的平台；用词偏好照常生效。

### 页面上的界面不被广告拦截藏掉

确认框和状态小条挂在 `<html>` 下的自定义元素 `huaci-site-ui` 上，宿主样式写在 closed shadow root 的 `:host` 里并加 `!important`，宿主本身没有 `style` 属性。原因：广告拦截扩展会注入 `head ~ div[style*="z-index"] { display: none !important; … }` 这类规则（用户的 Chrome 里 Stands AdBlocker 实测如此），最早用 `div` + 内联 `z-index` 时整个界面被藏成 0×0，表现为「点了没反应」。shadow root 里的 `!important` 在层叠中胜过外部文档的 `!important`，所以网页和拦截器都盖不过；端到端脚本里加了同样的规则做回归检查。其他模块的浮层挂在 `<body>` 下，不匹配这条规则，但同类规则同样可能影响它们。

### 省用量

- **只翻译视口附近的内容**：文字所在元素交给 `IntersectionObserver`（上下各预留 600px），滚到附近才排队。隐藏的内容（`display: none` 的菜单、折叠面板）不会被翻译。
- **相同文字只请求一次**：同一页面里按去掉首尾空白的原文缓存译文（最多 3000 条），批内也去重。导航、页脚这类重复文字只花一次。
- **页面已经是目标语言时不翻译**：先看 `<html lang>`；没有声明时取正文开头两千字，假名占汉字与假名合计两成以上就算日文（`AITrLang.looksJapanese`），否则用 `chrome.i18n.detectLanguage` 识别。浏览器识别汉字多的日文（如只有版块名的目录页）不可靠，所以先看假名。目标是中文时，本来就是中文的文字节点也跳过（页面是另一种中文时照常做简繁转换）；但日文页面里只有汉字的段落（「不倫・浮気」「経済」）是日文，不跳过。2ch 版块目录 949 段里曾有 393 段因此被当成中文、原样留下。
- 每批最多 50 段、2200 字（区域翻译相同），同时最多 2 个请求。短段落多的页面（目录、菜单）一批能看到更多上下文，前后译法更一致，系统提示词也少重复发送。
- 大模型偶尔少回、多回一条或回复不是合法的 JSON 数组时，这一批自动拆成两半重发，直到单段，单段仍不对改用普通文字翻译（自带 Key 在扩展里拆，点数翻译在后台用同一模型拆，仍失败再改用备用模型）。平台拒绝处理的段落（DeepSeek 对政治敏感内容返回 `finish_reason: content_filter`、内容为空，换纯文字请求也一样）同样靠拆半隔离出来，保留原文、不进缓存，其余照常翻译，不报错；页面空闲时右下角提示有几段被拒绝翻译，「查看」逐段滚过去并在扩展自己的 shadow root 里画框标出（不改网页元素），有新的被拒段落时再提示。网络、额度等其他错误停止排队，等用户点「重试」，不会一直重试烧用量。

## 三、隐私

网站名单只存在本机 `chrome.storage.local`，不同步、不上传。翻译的文字与其他功能一样只发给所选平台（本机翻译不出本机）。

2.3.0 发布准备已更新 `PRIVACY.md` 与官网隐私政策：补充开启网站的视口附近文字、以后访问自动生效、平台选择和本机翻译不上传；官网介绍与更新日志同步维护。实际部署与商店状态见发布记录。

## 四、验证

- `test/menu.mjs` 覆盖菜单与确认流程。
- 端到端脚本（本机，不入库）：无头 Chrome for Testing 150 加载未打包扩展，在 service worker 里把 `AITrProviders.translateBatch` 换成桩，打开本地测试页，确认：首屏翻译、开放 shadow root 里的文字、中文页面不发请求并显示说明、开启后立即出现「正在翻译」、链接保留、代码 / `.notranslate` / 中文不动、远处内容滚动后才翻、重复文字不再请求、动态插入的内容会翻、页面改过的文字重新翻、关闭后恢复原文且保留页面改动、再次开启不用刷新、改平台后用新平台重翻、出错小条、确认框（截图、Esc 取消、点「改用本机翻译」）、设置页列出与移除网站。
- 框架端到端脚本（本机，不入库，`tools/capture/site-frames-e2e.mjs`）：frameset 页面的菜单框架与子域名（跨源）内容框架、其中的嵌套 iframe 翻译，别的网站的 iframe 不翻也不发请求（即使其域名在名单上），只开子域名时嵌在上级域名页面里的子域名框架不翻，直接打开子域名页面也翻，框架内换页面后自动翻译，关闭后全部恢复原文。子域名的覆盖与开关规则另见 `test/sites.mjs`。
- 菜单点击的真实处理函数：用 DevTools 的 `Runtime.queryObjects` 找到 service worker 里的 `toggleSite`，按菜单点击的参数调用，确认弹出确认框、点「继续使用点数翻译」后开始请求（测试环境未登录，小条显示「请先登录账户」）。
- 还没在真实环境确认：原生右键菜单的勾选显示；本机翻译在 service worker 里能否创建翻译器（见 `local-translation.md` 第四节，整站翻译和划词一样走这里）；真实平台的用量；复杂网站（单页应用、大量动态内容）上的表现。

# 点词换说法与用词偏好

> 状态：已在本地实现（2026-11-06），**尚未打包发布**。后台改动（`/api/extension/alternatives`、`/translate` 的 `glossary`）需要随提交部署；部署前点数翻译模式下换说法会报错、偏好不会带进请求，自带 Key 模式不受影响。

## 一、用户能做什么

在下列地方，译文翻完后按词切开，鼠标移上去浅浅托起；点一个词，或拖选几个词，弹出「其他译法」：

| 位置 | 文件 | 原文标记 |
| --- | --- | --- |
| 双语阅读页 | `src/reader/` | 左侧对应段落里标出原文词语 |
| 划词弹窗（网页上，闭合 Shadow DOM） | `src/content/content.js` | 弹窗里折叠的「原文」 |
| 翻译面板 | `src/translate/` | 无 |
| 整份 PDF 翻译页 | `src/pdf/` | 无（原文是页面图片） |

弹窗里：选中的词与它对应的原文词语；最多 5 个可以直接替换的说法，各带一句很短的区别说明（界面语言）；输入框自己改写；改过的段落可以「恢复这一段的原译文」。键盘上下选择，Esc 只关弹窗。

替换之后：

- 译文立即更新（复制按钮复制的是换过的译文；PDF 块会重新缩放字号放进原位）。
- 知道对应的原文词语时，记成一条**用词偏好**（例如 `功能 → feature`，目标语言英文），提示条写明「以后翻译「功能」会优先用这个译法」，可以「不要记住」。
- 别处还有同一个词时（阅读页、PDF 的其他段落），提示条提供「全部替换」。

**用词偏好**之后自动用于所有文字翻译：划词、翻译面板、区域翻译、双语阅读、整份 PDF、图片里的文字（视频字幕除外）。设置页「用词偏好」一节列出全部条目，可以单条删除或全部清除。

没有接入换说法的地方：区域翻译（译文写在网页自己的 DOM 里，给网页内容逐词套元素会干扰网站）、图片翻译（译文画在图片上）、视频字幕（已暂停）。这些地方的翻译仍会应用用词偏好。

## 二、实现

### 1. 通用模块 `src/lib/word-picker.js`

- `AITrWordPicker.create({ root, mount, units, target, request, remember, forget, onChange, cacheKey })`，返回 `paint / close / reset / destroy`。
- 译文单元 `{ node, text, out, machine, src? }`：`paint(unit)` 用 `Intl.Segmenter(目标语言, { granularity: 'word' })` 把 `out` 切成 `span.wp-w`，记下每个词在译文里的起止位置；流式翻译在翻完后才切，过程中保持纯文字。
- 点词取该词；拖选时用 Range 算出在这一段译文里的起止位置（只处理同一段内），去掉两端空白，最长 200 个字符。Shadow DOM 里从根上取选区。
- 同一段、同一位置、同一译文、同一平台只请求一次：缓存的是请求本身，关掉再点、双击选词都不会重复扣点；`reset()` 在换语言、平台或重新翻译时清空。
- 弹窗与提示条 `position: fixed`，放进 `mount`（扩展页面是 `body`，划词弹窗是它自己的 Shadow DOM），滚动时跟着锚点走。配色读 `--wp-*` 变量（阅读页映射到阅读主题），没有时按系统浅色 / 深色取默认值。

### 2. 取其他译法 `AITrProviders.alternatives`

- 把原文段落、选中部分以及它前后的译文分开发给模型（JSON），要求最多 5 个能直接放回原句的说法、附简短说明，并指出对应的原文词语；回复只保留文字与说明，去掉与当前选中相同或重复的项。
- 文字超过 3600 个字符时只取选中位置附近的一段（原文按选中位置在译文里的比例取对应的一段）。
- 大模型平台（OpenAI 兼容、DeepSeek）直接请求；点数翻译走后台 `POST /api/extension/alternatives`（按原文段落字数扣点，见 `docs/backend/credit-accounting.md`）；DeepL 没有这项能力，弹窗提示不支持，仍可自己改写（此时不知道原文词语，不记偏好）。
- 划词弹窗在内容脚本里，经 service worker 的 `ai-translation-request` 端口（`type: 'alternatives'`）代发，断开即取消。
- 提示词在扩展 `providers.js` 与后台 `hosted.js` 各有一份（`alternativesPrompt`），`test/alternatives.mjs` 检查两边一致。

### 3. 用词偏好 `src/lib/terms.js`

- 存在 `chrome.storage.local` 的 `termPrefs`，只在这个浏览器里，不经 Chrome 账号同步，后台不保存。每条 `{ id, source, from, to, target, at }`；同一目标语言、同一原文词语只留最新一条，最多 500 条。
- 内容脚本不直接写：划词弹窗经 service worker 的 `terms-remember` / `terms-forget` 消息（只接受本扩展的页面与内容脚本）。
- 匹配：目标语言相同，且原文里出现这个原文词语。中日韩、泰文按字面匹配，其他文字按整词、不分大小写（`app` 不会匹配 `apps`）。每次最多带 20 条，最新的优先。
- 应用：
  - 大模型平台：系统提示词末尾加一行「读者偏好这些译法（JSON：原文词语 → 译法），出现时照此翻译，只调整大小写或词形」。单段、批量都加。
  - 点数翻译：随 `/translate` 请求带 `glossary: [{ source, target }]`，后台只放进提示词，不保存、不计费（每项 1–100 个字符，最多 20 条）。
  - DeepL：没有这种入口；原文里有这个词、译文里还是原来的译法（整词）时，替换成偏好的译法。

## 三、隐私

- 用词偏好只保存在本机；翻译时把相关条目（原文词语与译法）随请求发给所选平台或点数服务，与待翻译的文字同样处理，点数服务不保存。
- 换说法会把原文段落与整段译文发给所选平台或点数服务，与重新翻译这一段相同。

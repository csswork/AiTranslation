# 整份视频翻译

右键网页里的视频，选「翻译这个视频」：扩展把整个视频文件取下来，识别出完整文稿，整篇一次翻译，带时间轴整套交给页面，按播放时间显示双语字幕；翻好的视频连同字幕存进「视频翻译」页。面向 9GAG 这类直链短视频；可行性与实测数据见 `video-audio-translation.md` 第十节和本机的 `tools/video-file-probe/`。

和「视频实时字幕（实验）」的区别：实时字幕截取标签页声音边播边识别、逐行翻译，碎片多、译文晚；整份翻译先拿到完整文稿再分句、整篇翻译，不依赖视频是否在播放、是否静音（9GAG 默认静音自动播放）。

## 入口与分流

视频只有一个右键菜单项「翻译这个视频」（`contexts: ['video']`，常驻；Firefox 没有 offscreen 文档，不建）。点击后在 `background.js` 的 `translateVideo` 分流：

1. 这个标签页正开着实时字幕：关掉（与原来「再点一次就关」一致）。
2. 视频地址是 http(s) 直链：整份翻译（`AITrVideoFile.open`）。翻过的（视频翻译记录里有同一地址、同样的平台 / 目标语言 / 识别语言）直接给字幕；同一个视频正在翻就让新浮层接上进度；同时最多翻 3 个。
3. 地址是 `blob:` 等（YouTube、X 这类分段串流）：打开了实时字幕（实验）就改走实时字幕，否则浮层说明没法整份翻译。

菜单项各自的 `contexts` 两两不重叠，所以不另加第二个视频项（重叠会被 Chrome 折叠进子菜单，见 `test/menu.mjs`）。

「视频翻译」页（`src/videos/`）的其他入口：扩展图标弹窗的「视频翻译」、设置页视频卡片的「查看翻好的视频」、浮层的「新页面看」、右下角的完成卡片。

## 流程

```
右键视频 → background.translateVideo → AITrVideoFile.open（lib/video-file.js）
  注入 content/video-file.js（字幕浮层），发 { video-file-open, jobId }（或直接带上翻过的字幕）
浮层 → 长连接 ai-video-file，带 jobId 认领（只认登记时的标签页与框架）
service worker → offscreen（offscreen/file.js）：video-file-start { jobId, url, candidates | lang, mode, store }
  取文件（不带 Cookie 与 Referer，≤ 100 MB，第一块就按文件头确认是音视频）；store 时存一份视频文件到记录
  解码音轨 → 16 kHz 单声道（≤ 10 分钟）；整段静音就直接报没有声音
  mode 'local'：先判断语言——candidates 里装了语言包的前 3 种同时听（每种一路 MediaStreamDestination，不出声）；
    听够了报 judge，service worker 判断后回 video-file-judged，选中的一路继续听到底；
    判断不了报 need-lang，等用户选（video-file-lang）后从头按它听
  mode 'audio'：编成 WAV 交回
  进度、结果用 video-file-event 报回（每秒一次，顺带让 service worker 保持运行）
service worker：mode 'audio' 时 AITrProviders.transcribe（OpenAI whisper-1）
  → AITrProviders.translateTranscript → 带时间的字幕 → 存进视频翻译记录（lib/video-library.js）→ 浮层
  → 用户不在那一页时，在正在看的网页右下角弹完成卡片
浮层：按 video.currentTime 显示「译文大字 + 原文小字」；跟随视频位置、大小与全屏
```

- 视频地址只用右键菜单给的 `info.srcUrl`。浮层只能凭 jobId 认领任务，不能提交网址；offscreen 只接受 service worker 的消息（`sender.tab` 为空）。不要改成让内容脚本传网址。
- **任务不跟着浮层走**：本机识别要花和视频一样长的时间，关掉浮层、刷新、跳走、视频被页面回收都只是不再显示，翻译在后台做完；只有浮层或「视频翻译」页里点「取消」才停（同时删掉已存的视频文件）。
- offscreen 读不到设置和界面语言，只报错误代码（`fetch-failed`、`too-large`、`too-long`、`not-media`、`no-audio`、`sr-unsupported`、`pack-*`、`sr-error`），文案由 `AITrVideoFile.offscreenError` 生成。

## 浮层与完成卡片

- 浮层（进度、字幕、左上角那条）只贴在视频上：用视频的完整位置，视频滚出窗口它也跟着滚出去，不停在窗口里；视频被隐藏时不显示。
- 处理中：视频下方显示进度（读取视频的百分比、「正在判断视频说的是什么语言（试听：英语、日语）…」、「正在按英语识别语音（12 / 116 秒）…」与进度条、翻译中）、「取消」和一行「可以先去看别的网页，翻好后会在右下角提示」。
- 判断不出语言：浮层里列出语言让用户选（装了语言包的可选，没装的灰掉，带「去设置」去下载），选了从头识别；浮层关着时右下角卡片提示去「视频翻译」页选，那里正在翻的一栏里有同样的下拉框。
- 字幕准备好时：视频停着（9GAG 帖子页默认停着）或已播完就从头播放，正在播的不打断；提示「边播边显示，也可以点「全部字幕」直接看」。只在有人说话的时间段出字幕，所以左上角常驻一条「双语字幕 · 全部字幕 · 新页面看 · ×」，视频停着时多一个「播放」。「全部字幕」打开整篇双语对照，点一句就跳到那里播放。
- 翻译时大模型仍觉得语言不对（见下文）：字幕照常显示，提示一直留着。
- 没有可显示的字幕（没有声音、没识别到人声）：提示几秒后自动收起。
- **完成卡片**：翻完时浮层不在、或用户不在那一页，就用 `scripting.executeScript` 在当前窗口正在看的网页右下角注入一张小卡片（closed shadow root，只用传进去的文字），点开是「视频翻译」页的那一条；那一页注入不了（扩展页、受保护的页面）就弹回原来那一页。翻译失败、没识别到人声也弹（没有链接）。不用 `notifications` 权限：它会多出「显示通知」的安装警告（实测），扩展更新后会被停用到用户同意为止。

## 视频翻译记录与「视频翻译」页

- `lib/video-library.js`：扩展自己的 IndexedDB（`aitr-videos`），`entries` 存标题、原网页、字幕、时长、识别语言、提醒等，`files` 存下载下来的视频文件（offscreen 写，同属扩展来源）。只在这个浏览器里，不上传、不同步；最多留最近 30 条、文件合计 500 MB，超出删最旧的。无痕窗口里的翻译不记。
- 「视频翻译」页：左边是正在翻的视频（每秒问后台 `video-file-jobs`，带进度和「取消」）与翻好的视频；右边是播放器（优先播存下的文件，没有就用原网址）、双语字幕、整篇字幕（点一句跳过去，当前句高亮）、原网页链接和删除（点两下）。地址里的 `#id` 选中那一条。

## 识别

| 翻译平台 | 识别 | 说明 |
| --- | --- | --- |
| ChatGPT（有 Key） | OpenAI `whisper-1`，`verbose_json`，词级 + 段级时间 | 自动判断语种，几秒出结果；发往用户填的 Base URL 的 `/audio/transcriptions`。结果按音频内容缓存在本机 |
| 其他（DeepSeek、DeepL、本机翻译、点数翻译） | 浏览器设备端识别 | 声音不出浏览器；要有识别语言的离线语言包；只能 1 倍速，等待时间 = 视频时长 |

- **先判断语言，不直接用设置里的语言**：设备端识别不会自己判断语种，按错的语言听出来的是一串读不通的词（用户反馈「一塌糊涂」的 abeXRK9，116 秒多人对话：按英语识别 371 个词、几乎完整；按中文识别只出 15 个词）。所以每次先判断：
  - 候选按可能性排：网页的语言（`tabs.detectLanguage`）、实时字幕设置里固定的语言、界面语言、英语，然后其余语言（`AITrVideoFile.candidatesFor`）。offscreen 只取装了离线语言包的前 3 种，同时各开一路识别听同一段声音。
  - 听满 20 秒且有一路攒到 15 个词（或听满 45 秒且有一路至少 3 个词，或片子放完）时，把各路文字交给 service worker 判断：大模型平台请模型看哪一路读得通（`judgeSpokenLanguage`，温度 0，只认候选里的），其余平台按识别出的词密度（`AITrTranscript.judgeByDensity`：最密的每秒不到 0.6 个词、或不到第二名的 1.5 倍都算判断不了）。选中的那一路继续听到底、其余停掉，判断语言不额外花时间（abeXRK9 三路试听，21 秒判出英语，总共 127 秒，和直接按英语识别一样）。
  - 判断不了：请用户选，选了从头按它识别。整段几乎没人说话（各路都不到 3 个词）时不问，直接按「没有识别到人声」结束。
  - 一个语言包都没装：报错，带「去设置」。设置页的视频卡片里选语言下载语言包，并列出已下载的语言。
- **翻译时的二次检查**：大模型切句时顺带回 `lang` 和 `garbled`（识别结果整体读不通）。仍然读不通（比如用户选错了语言）或模型认为说的是别的语言，就提醒。读不通时不报模型猜的语言：从乱码里猜不准（探针：日语按英语听出的乱码被猜成西班牙语）。
- 设备端识别没有词级时间：每个词取它第一次出现在中间结果里的时刻，减 0.7 秒识别延迟（`AITrTranscript.timedTokens`）。时间按 `AudioContext.currentTime` 算：offscreen 里的音频上下文刚建好时可能还没跑起来，按墙上时间会整体偏晚约 3 秒（实测）。
- 2 倍速播放给识别器几乎认不出字（探针实测），不要为了省时间加速。
- Whisper 在纯音乐上会编句子：段落 `no_speech_prob > 0.6` 且 `avg_logprob < -1`、或 `compression_ratio > 2.4`、或 `avg_logprob < -1.5` 时整段丢掉（`AITrTranscript.fromWhisper`）。设备端识别在没人说话时基本零输出，不需要过滤。
- 中日文等不加空格的语言按 `Intl.Segmenter` 分词。

## 翻译

`AITrProviders.translateTranscript`（计入功能统计的 `subtitle`），返回 `{ cues, check: { lang, garbled } }`：

- **大模型（ChatGPT、DeepSeek）**：一次请求同时切句和翻译。用户消息是 `{ title, heard, tokens: [[序号, 词], …] }`（`heard` 是识别语言），模型按序号范围返回 `{ lang, garbled, cues: [{ from, to, text, tr }] }`，不抄原文，对齐不会错位（探针里让模型抄原文时 16 个视频错位 3 个）。提示词要求每条最多约 12 个英文单词、宁短勿长，并按意思判断谁在说哪句、换人处断开。请求带 `response_format: json_object`，沿用各平台的翻译调参（DeepSeek 关思考：探针里开思考慢到 47 秒且质量差别不大），只把温度降到 0.7（`CUE_TEMPERATURE`）：用 1.3 时同一段 127 个词切出 12 到 34 条，偶尔一条 29 个词；0.7 时稳定在 19 到 25 条。提示词末尾加风格指南与用词偏好。超过 600 个词的文稿在最长停顿处分段并行请求。回复不合格（越界、重叠、缺译文）时重试一次，还不对这一段退回下面的做法。结果缓存在本机（`llm-cues-2`）。
- 不给模型词的时间：设备端识别的词时间按结果到达的批次推算，词间「停顿」大多是识别器的节奏（探针里 0.6–0.9 秒的间隔一半落在句子中间，如「Harry ‖ you're not coming」），标给模型没有改善换人处的断句。
- 已知不足：语速快、多人抢话时，偶尔把下一个人的话头接到上一句（如「…a new boyfriend / in your dreams, Axel」被当成一句），设备端识别没有标点和说话人信息，模型也分不清。
- **DeepL、本机翻译、点数翻译**：按停顿（0.9 秒）、句末标点和长度（12 个词 / 18 个不加空格语言的词）切句，再走 `translateBatch` 整批翻译（同一批里有前后文）。没有大模型切句，句子常从中间断开，质量明显不如上面（探针：「…a new boyfriend in / your dreams Axel…」），也判断不了识别语言是否选错。
- 每句显示到下一句开始或最后一个词后 0.8 秒，至少 1.2 秒，不越过下一句（`AITrTranscript.cueTimes`）。识别器在音频放完后才吐出的词，时间会落在片尾之后，这类句子挪回片尾前，否则播不到。

## 限制

- 只支持能整份下载的 http(s) 视频文件：≤ 100 MB、≤ 10 分钟、能解出音轨。分段串流（`blob:`）、HLS 播放列表、DRM 都不行。
- 取文件不带 Cookie：要登录才能看的视频取不到。不带 Referer：要求特定 Referer 的防盗链取不到。
- 设备端识别只能从装了语言包的语言里判断；视频说的语言没装语言包时只能请用户先去下载。混着几种语言说的视频会认错（探针里英日混说的视频成了乱码）。
- 画面里烧录的字幕、梗图标题不翻（那是图片翻译的范围）。

## 发布前

- 更新隐私说明（`PRIVACY.md` 与官网 `privacy.html`，中英文）：整份视频翻译时扩展会下载视频文件、在本机解码，并把视频文件与字幕存在本机（视频翻译记录，最多 30 个、不上传）；翻译平台是 ChatGPT 时视频的声音发给 OpenAI 转写，其余平台声音不离开浏览器；识别出的文字按翻译模式发给翻译平台或我们的服务器。核对商店数据声明。

## 验证

- 单元测试：`test/transcript.mjs`（词时间、切句、回复校验、Whisper 过滤、WAV、容器识别）、`test/video-file.mjs`（大模型 / DeepL 翻译、重试与退回、OpenAI 转写请求、错误文案、选错语言的提醒、自动识别语言）、`test/menu.mjs`（菜单项常驻、分流、同一视频接上原来那一路）。
- 真实 Chrome（`tools/video-file-probe/`，不进 git）：用 CDP `Extensions.loadUnpacked` 加载扩展，调用与右键菜单相同的 `AITrVideoFile.open`，用 CDP 穿透 closed shadow root 读浮层和卡片的文字、按坐标点按钮。`e2e-extension.mjs` 核对字幕时间（`GAG=1` 用 9GAG 帖子页结构与真实 CDN 视频）；`e2e-flow.mjs` 走一遍「关掉浮层 → 换到别的网页 → 右下角卡片 → 点开视频翻译页播放存下的文件」；`e2e-detect.mjs en|multi|pick` 验证判断语言（只装英语包、三种语言包同时试听、日语声音只装英语包时请用户选）以及浮层跟着视频滚出窗口。`cue-eval.mjs` 用存下的识别日志单独评估切句与翻译。真实 9GAG 页面对自动化浏览器有 Cloudflare 人机验证，没法直接跑；CDP 点不到原生右键菜单，菜单本身由 `test/menu.mjs` 覆盖。
